# BlueBee IoT — Replit Agent Specification

## 1. IDENTIDADE DO PROJETO

**Produto:** BlueBee IoT — Plataforma supervisória SaaS multi-tenant para monitoramento remoto de sistemas BMS (Building Management System: climatização, energia, hidráulica).

**Operadora:** Autobras BlueBee (integradora BMS). Ela NÃO é um tenant — é a operadora da plataforma. Cada cliente da Autobras é um tenant com isolamento total de dados.

**Repositório:** `github.com/claucio-autobras/BlueBee.git`
**Branch de trabalho:** `develop`
**Branch de produção:** `main` — NUNCA fazer push direto sem autorização explícita.

## 7. HIERARQUIA DE DADOS (multi-tenant)

```
Tenant (cliente da Autobras)
  └── Site (localidade física)
        └── Project (sistema BMS implantado)
              ├── Gateway (dispositivo de borda .exe)
              └── Device (controladora BMS)
                    └── DevicePoint (ponto monitorado / tag)
                          ├── Trend → TrendRecord (histórico)
                          └── AlarmRule → AlarmEvent (alarme)
```

**Regra de ouro — NUNCA violar:** toda query Prisma que retorna dados de negócio DEVE filtrar por `tenant_id`. Perfis globais (ADMIN, CCO, SUPERVISOR) têm `tenant_id = null` e enxergam todos os tenants.

## 9. SCHEMA DO BANCO (Prisma)

O schema completo está em `apps/backend/prisma/schema.prisma`.

**Tabelas principais:**

| Tabela | Papel |
|--------|-------|
| `tenants` | Raiz do isolamento multi-tenant |
| `users` | Usuário; auth bcrypt; tenant_id null = perfil global |
| `sites` | Localidade física do cliente |
| `projects` | Sistema BMS; flag scada_enabled |
| `gateways` | Borda; mqtt_user/pass; status via last_seen |
| `devices` | Controladora; protocol, ip, port (47808 BACnet) |
| `device_points` | Ponto monitorado; chave (device, object_type, instance) |
| `trends` | Config de histórico opt-in por ponto |
| `trend_records` | Série temporal; BigInt PK; hypertable TimescaleDB |
| `alarm_rules` | Configuração de alarme por ponto |
| `alarm_events` | Ocorrência; máquina de estados |
| `scada_screens` | Tela sinótica em JSON; binding por objectType:instance |
| `telemetry` | Leitura genérica auxiliar |

**Enums:**
- `Role`: ADMIN, CCO, SUPERVISOR, CLIENTE, VISUALIZADOR
- `TrendMode`: ON_CHANGE, INTERVAL
- `AlarmSeverity`: LOW, MEDIUM, HIGH
- `AlarmEventState`: ACTIVE, ACTIVE_ACK, NORMALIZED_UNACK, NORMALIZED_ACK

**Ativar TimescaleDB (rodar uma vez no banco):**
```sql
CREATE EXTENSION IF NOT EXISTS timescaledb;
SELECT create_hypertable('trend_records', 'timestamp', chunk_time_interval => INTERVAL '1 day');
SELECT add_compression_policy('trend_records', INTERVAL '7 days');
SELECT add_retention_policy('trend_records', INTERVAL '365 days');
```

**Setup do banco:**
```bash
cd apps/backend
npx prisma migrate deploy
npm run seed
```

## 10. AUTENTICAÇÃO (JWT próprio — SEM Supabase)

O BlueBee NÃO usa Supabase Auth nem Replit Auth. A autenticação é implementada integralmente no NestJS:

1. Usuário envia `POST /auth/login` com `{ email, senha }`
2. Backend busca no PostgreSQL por email
3. Compara senha com hash bcrypt
4. Assina JWT próprio: `{ sub, email, role, tenantId }` — expira em 8h
5. Frontend armazena JWT no Zustand store
6. Todo request inclui `Authorization: Bearer <token>`
7. `JwtAuthGuard` + `RolesGuard` + `tenant.middleware` protegem todas as rotas

## 11. COMUNICAÇÃO MQTT

**Broker:** HiveMQ Cloud (externo, free tier → Standard com 100+ gateways)

**Tópicos:**
```
bluebee/{tenantId}/gateway/{gwId}/telemetry     → Gateway para backend (QoS 0)
bluebee/{tenantId}/gateway/{gwId}/config        → Backend para gateway (QoS 1, retained)
bluebee/{tenantId}/gateway/{gwId}/commands      → Backend para gateway (QoS 1)
bluebee/{tenantId}/gateway/{gwId}/commands/result → Gateway para backend (QoS 0)
```

**Payload de telemetria:**
```json
{
  "deviceId": "<uuid>",
  "tenantId": "<uuid>",
  "timestamp": "2026-06-19T10:00:00Z",
  "points": [
    { "tag": "temp_saida", "objectType": 0, "objectInstance": 1, "value": 7.2, "unit": "grC" }
  ]
}
```

## 13. MÓDULOS DO BACKEND (NestJS)

Cada módulo segue DDD: `domain/` → `application/` → `infrastructure/` → `presentation/`.
Controllers NUNCA acessam Prisma diretamente — sempre via service.
Imports SEMPRE com sufixo `.js` (ESM obrigatório).

| Módulo | Responsabilidade |
|--------|-----------------|
| `auth` | bcrypt + JWT; POST /auth/login, GET /auth/me |
| `tenants` | CRUD de clientes (só ADMIN) |
| `sites` | Localidades físicas |
| `projects` | Sistemas por site + scadaEnabled |
| `gateways` | Status ao vivo + credenciais MQTT |
| `devices` | Controladoras + discovery BACnet |
| `device-points` | CRUD de pontos + republica config MQTT |
| `mqtt` | Cliente MQTT + BacnetMqttSubscriber |
| `telemetry-gateway` | Socket.IO — empurra telemetria ao browser |
| `trends` | Histórico opt-in + retenção por cron |
| `alarms` | Regras + eventos + ACK + tempo real |
| `scada` | Telas sinóticas + assets em disco |
| `reports` | CSV/PDF — jsPDF + jspdf-autotable |
| `dashboard` | KPIs consolidados por tenant |

## 18. CONTEXTO DE ESCALABILIDADE

- **PostgreSQL (Neon):** escala automaticamente — sem limite de armazenamento
- **TimescaleDB 2.13:** disponível nativamente no Replit — ativar na Fase 5
- **HiveMQ free tier:** limite de 100 conexões simultâneas — upgrade para Standard com 80+ gateways
- **Reserved VM:** único ponto de atenção com 30-50+ clientes simultâneos — monitorar CPU/memória
- **Código não muda entre ambientes** — apenas variáveis de ambiente apontam para nova infra
