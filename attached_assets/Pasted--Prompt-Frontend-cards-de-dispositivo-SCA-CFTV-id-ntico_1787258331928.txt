## 0. Regras de tema — leia antes de escrever qualquer classe

O projeto usa **Tailwind v4** com tokens em `@theme` (`apps/frontend/src/app/globals.css`) e tema escuro por **classe** (`@custom-variant dark (&:where(.dark, .dark *))`, com um bloco `.dark` que sobrescreve os tokens).

Três fatos que determinam como escrever as classes:

1. **Tokens semânticos viram do tema sozinhos.** `bg-card`, `bg-background`, `bg-muted`, `text-foreground`, `text-muted-foreground`, `border-border`, `text-primary`, `bg-primary` já têm valor próprio em light e em dark. **Use sempre estes** para superfície, texto e borda.

2. **O bloco `.dark` remapeia os tints claros da paleta.** `--color-emerald-100`, `--color-red-100`, `--color-amber-100`, `--color-slate-50..600`, `cyan/blue/orange/purple -50/-100/-200` recebem equivalentes escuros sob `.dark`. Por isso `bg-emerald-100` continua legível no tema escuro. Mesmo assim, o padrão do código nas *pills* de status é declarar o par explícito — **copie exatamente**:
   - online → `bg-emerald-100 text-emerald-700 dark:bg-emerald-500/15 dark:text-emerald-400`
   - offline → `bg-red-100 text-red-700 dark:bg-red-500/15 dark:text-red-400`
   - alerta → `text-amber-600 dark:text-amber-400`
   - sem dados → `bg-muted text-muted-foreground` (sem variante dark: o token já vira)

3. **Tons sólidos médios NÃO são remapeados** — `bg-emerald-500`, `bg-red-500`, `bg-amber-500`, `bg-slate-400`, `bg-primary` têm o mesmo valor nos dois temas. Isso é intencional: são usados no ponto do status e nas barras de progresso, onde o contraste funciona em light e dark.

**Proibido** (quebra um dos dois temas): `bg-white`, `bg-black`, `text-black`, `bg-gray-*`, `text-gray-*`, `bg-slate-800/900`, qualquer hex/rgb literal em `className`, e `style` com cor. A única propriedade aceitável em `style` é a **largura da barra de progresso** (`width: ${pct}%`), porque é valor dinâmico, não cor.

**O erro cometido na tentativa anterior foi exatamente este:** o card e as tiles receberam uma superfície escura fixa. No tema escuro parece certo; no tema claro o texto — que usa token semântico e portanto vira para escuro — fica escuro sobre fundo escuro, e título e rótulos somem. Se você precisa escrever a cor de um fundo, **está errado**: use `bg-card` no card e `bg-muted/30` na tile, e não declare mais nada.

Como verificar: abra as duas telas, alterne o tema pela interface e confirme que **todo** texto continua legível. Não considere o item pronto tendo olhado só um tema.

Todos os componentes novos precisam de `'use client'` na primeira linha (usam estado/eventos e são renderizados dentro de páginas client).

## 1. Arquivo novo — `apps/frontend/src/components/health-metrics.ts`

Builder **puro** (sem JSX) que transforma os pontos do dispositivo nas tiles do card. É o que torna o card dinâmico e é compartilhado por SCA e CFTV. Crie exatamente assim:

```ts
/**
 * Builder das tiles de saúde de hardware de um dispositivo SNMP.
 *
 * Compartilhado entre SCA (controladoras) e CFTV (câmeras/NVRs) — qualquer
 * dispositivo monitorado via SNMP usa as mesmas métricas canônicas. O builder
 * é DINÂMICO: gera tiles só para as métricas que o dispositivo tem ponto,
 * deriva "memória usada %" quando dá (disponível + total presentes) e
 * preserva os estados "sem dados" / "não suportado" por tile.
 *
 * Puro e testável: recebe os pontos + uma função de leitura de telemetria.
 */

/** Ponto mínimo necessário para montar as tiles (shape de SCA e CFTV). */
export interface HealthPointLike {
  tag: string;
  metric: string;
  unit: string;
  unsupported?: boolean;
}

/** Leitura de telemetria de um ponto (subset do retorno de liveOrSeed). */
export interface HealthReading {
  value: number | string | null;
  unreliable?: boolean;
}

/** Tile pronta para renderização. */
export interface HealthTile {
  key: string;
  label: string;
  /** Valor formatado ("20%", "31,0 MB") — ou null quando sem valor. */
  text: string | null;
  /** Estado quando text === null. */
  emptyState: 'sem dados' | 'não suportado' | null;
  /** Percentual 0–100 para a barra de progresso (null = sem barra). */
  pct: number | null;
  unreliable: boolean;
  /** Tooltip opcional (ex.: "31,0 MB livres de 117 MB"). */
  title?: string;
}

/** Formata megabytes com auto-escala ("31,0 MB", "1,2 GB"). */
export function formatMb(mb: number): string {
  if (mb >= 1024) return `${(mb / 1024).toFixed(1)} GB`;
  return `${mb >= 100 ? Math.round(mb) : mb.toFixed(1)} MB`;
}

/** Limita a [0, 100] para a barra de progresso. */
function clampPct(v: number): number {
  return Math.max(0, Math.min(100, v));
}

interface MetricValue {
  point: HealthPointLike;
  value: number | null;
  unreliable: boolean;
}

/**
 * Monta as tiles na ordem canônica:
 *   CPU → Memória usada % → Memória RAM (total) → Memória disp. →
 *   Temperatura → Pacotes perdidos → Perda ping → Armazenamento.
 *
 * "Memória usada %" é derivada de disponível (kB) + total (MB) quando ambos
 * existem — ou vem direta quando o ponto memory é percentual (Hikvision).
 * Nesse caso a tile "Memória disp." é omitida para não duplicar informação.
 */
export function buildHealthTiles(
  points: HealthPointLike[],
  read: (tag: string) => HealthReading | null | undefined,
): HealthTile[] {
  const metricOf = (metric: string): MetricValue | null => {
    const point = points.find((p) => p.metric === metric);
    if (!point) return null;
    const entry = read(point.tag);
    const n = Number(entry?.value);
    const has = entry?.value !== null && entry?.value !== undefined && Number.isFinite(n);
    return { point, value: has ? n : null, unreliable: has && entry?.unreliable === true };
  };

  const tile = (
    key: string,
    label: string,
    m: MetricValue,
    text: string | null,
    pct: number | null = null,
    title?: string,
  ): HealthTile => ({
    key,
    label,
    text,
    emptyState: text !== null ? null : m.point.unsupported ? 'não suportado' : 'sem dados',
    pct,
    unreliable: m.unreliable,
    title,
  });

  const tiles: HealthTile[] = [];

  // ── CPU ────────────────────────────────────────────────────────────────────
  const cpu = metricOf('cpu');
  if (cpu) {
    tiles.push(
      tile(
        'cpu',
        'Uso de CPU',
        cpu,
        cpu.value !== null ? `${Math.round(cpu.value)}%` : null,
        cpu.value !== null ? clampPct(cpu.value) : null,
      ),
    );
  }

  // ── Memória ────────────────────────────────────────────────────────────────
  const memory = metricOf('memory');
  const ramTotal = metricOf('ram_total');
  const memoryIsPct = memory !== null && memory.point.unit.trim() === '%';
  const totalMb = ramTotal?.value ?? null;
  const availMb =
    memory && !memoryIsPct && memory.value !== null
      ? memory.point.unit.trim().toLowerCase() === 'kb'
        ? memory.value / 1024
        : memory.value // já em MB
      : null;

  if (memoryIsPct && memory) {
    // Firmware reporta uso de memória em % direto (ex.: Hikvision).
    tiles.push(
      tile(
        'memory_used',
        'Memória usada',
        memory,
        memory.value !== null ? `${Math.round(memory.value)}%` : null,
        memory.value !== null ? clampPct(memory.value) : null,
      ),
    );
  } else if (memory && availMb !== null && totalMb !== null && totalMb > 0) {
    // Derivada: usada% = 1 − disponível/total.
    const usedPct = clampPct(100 * (1 - availMb / totalMb));
    tiles.push(
      tile(
        'memory_used',
        'Memória usada',
        memory,
        `${Math.round(usedPct)}%`,
        usedPct,
        `${formatMb(availMb)} livres de ${formatMb(totalMb)}`,
      ),
    );
  } else if (memory) {
    // Sem total conhecido — mostra a disponível formatada.
    tiles.push(
      tile(
        'memory_avail',
        'Memória disp.',
        memory,
        availMb !== null ? formatMb(availMb) : null,
      ),
    );
  }

  if (ramTotal) {
    tiles.push(
      tile(
        'ram_total',
        'Memória RAM',
        ramTotal,
        totalMb !== null ? formatMb(totalMb) : null,
      ),
    );
  }

  // ── Temperatura ────────────────────────────────────────────────────────────
  const temperature = metricOf('temperature');
  if (temperature) {
    tiles.push(
      tile(
        'temperature',
        'Temperatura',
        temperature,
        temperature.value !== null ? `${temperature.value.toFixed(1)}°C` : null,
      ),
    );
  }

  // ── Rede ───────────────────────────────────────────────────────────────────
  const packetLoss = metricOf('packet_loss');
  if (packetLoss) {
    tiles.push(
      tile(
        'packet_loss',
        'Pacotes perdidos',
        packetLoss,
        packetLoss.value !== null ? `${Math.round(packetLoss.value)} pkts` : null,
      ),
    );
  }

  const pingLoss = metricOf('ping_loss');
  if (pingLoss) {
    tiles.push(
      tile(
        'ping_loss',
        'Perda ping',
        pingLoss,
        pingLoss.value !== null ? `${Math.round(pingLoss.value)}%` : null,
        pingLoss.value !== null ? clampPct(pingLoss.value) : null,
      ),
    );
  }

  // ── Armazenamento (câmeras/NVRs) ───────────────────────────────────────────
  const storage = metricOf('storage');
  if (storage) {
    tiles.push(
      tile(
        'storage',
        'Armazenamento',
        storage,
        storage.value !== null ? `${Math.round(storage.value)}%` : null,
        storage.value !== null ? clampPct(storage.value) : null,
      ),
    );
  }

  return tiles;
}
```

### Regras de negócio embutidas (não altere)

- **Dinâmico de verdade:** métrica sem ponto cadastrado **não gera tile**. Nunca renderize slot vazio para métrica que o equipamento não tem.
- **Memória usada é derivada**, não lida: `100 × (1 − disponível/total)`. O ponto `memory` vem em **kB** (UCD) e o `ram_total` em **MB** — a conversão está no builder.
- **Exceção Hikvision:** quando o ponto `memory` tem unidade `%`, o valor é uso direto; nesse caso **não** existe tile "Memória disp." (seria informação duplicada).
- **kB nunca aparece na UI.** `formatMb` escala para MB/GB.
- `unsupported` do ponto → texto **"não suportado"**; sem leitura ainda → **"sem dados"**. São estados diferentes e ambos precisam existir.

## 2. Arquivo novo — `apps/frontend/src/components/HealthMetricsGrid.tsx`

```tsx
'use client';

/**
 * HealthMetricsGrid — grade de tiles de saúde de hardware de um dispositivo
 * SNMP (controladora, câmera, NVR). Compartilhada entre SCA e CFTV.
 *
 * Cada tile: ícone + rótulo, valor em destaque e barra de progresso para
 * métricas percentuais (CPU, memória usada, perdas). A cor da barra reage ao
 * nível (normal → âmbar ≥75% → vermelho ≥90%). Estados "sem dados" e
 * "não suportado" preservados por tile, com tooltip explicativo.
 */

import {
  Cpu,
  Gauge,
  HardDrive,
  MemoryStick,
  Network,
  Thermometer,
  Wifi,
  type LucideIcon,
} from 'lucide-react';
import type { HealthTile } from './health-metrics';

const TILE_ICONS: Record<string, LucideIcon> = {
  cpu: Cpu,
  memory_used: Gauge,
  memory_avail: MemoryStick,
  ram_total: MemoryStick,
  temperature: Thermometer,
  packet_loss: Network,
  ping_loss: Wifi,
  storage: HardDrive,
};

/** Cor da barra por nível de uso/perda. */
function barColor(pct: number): string {
  if (pct >= 90) return 'bg-red-500';
  if (pct >= 75) return 'bg-amber-500';
  return 'bg-primary';
}

export function HealthMetricsGrid({ tiles }: { tiles: HealthTile[] }) {
  if (tiles.length === 0) return null;
  return (
    <div className="grid grid-cols-2 gap-2">
      {tiles.map((tile) => {
        const Icon = TILE_ICONS[tile.key] ?? Gauge;
        const has = tile.text !== null;
        return (
          <div
            key={tile.key}
            className="rounded-lg border border-border bg-muted/30 px-2.5 py-2 min-w-0"
            title={
              tile.unreliable
                ? 'Dado não confiável — o firmware responde um valor fixo neste OID.'
                : tile.emptyState === 'não suportado'
                  ? 'O equipamento não expõe esta métrica via SNMP (último diagnóstico).'
                  : tile.title
            }
          >
            <div className="flex items-center gap-1.5 min-w-0">
              <Icon
                className={`h-3.5 w-3.5 shrink-0 ${has ? 'text-primary' : 'text-muted-foreground/60'}`}
              />
              <p className="truncate text-[10px] font-medium uppercase tracking-wide text-muted-foreground">
                {tile.label}
              </p>
            </div>
            <p
              className={[
                'mt-0.5 truncate text-sm font-semibold',
                tile.unreliable
                  ? 'text-amber-600 dark:text-amber-400'
                  : has
                    ? 'text-foreground'
                    : 'text-muted-foreground font-normal text-xs',
              ].join(' ')}
            >
              {has ? `${tile.text}${tile.unreliable ? ' ⚠' : ''}` : tile.emptyState}
            </p>
            {tile.pct !== null && (
              <div className="mt-1.5 h-1 w-full overflow-hidden rounded-full bg-muted">
                <div
                  className={`h-full rounded-full transition-all ${barColor(tile.pct)}`}
                  style={{ width: `${tile.pct}%` }}
                />
              </div>
            )}
          </div>
        );
      })}
    </div>
  );
}
```

Detalhes que **não** podem mudar: grade de **2 colunas** (`grid-cols-2 gap-2`); fundo do tile `bg-muted/30` (funciona nos dois temas por ser o token com alfa); ícone `text-primary` quando há valor e `text-muted-foreground/60` quando não há; barra de **1px de altura** (`h-1`) com trilho `bg-muted`.

## 3. Arquivo novo — `apps/frontend/src/components/DeviceCardActionBar.tsx`

```tsx
'use client';

/**
 * DeviceCardActionBar — rodapé de ações dos cards de dispositivo (SCA/CFTV).
 *
 * Botões com ícone + rótulo (em vez de ícones soltos), tom neutro com
 * destaque no hover; ações destrutivas em vermelho. Compartilhado para os
 * cards de controladoras, câmeras e futuros tipos manterem o mesmo padrão.
 */

import type { LucideIcon } from 'lucide-react';

export interface CardAction {
  key: string;
  label: string;
  icon: LucideIcon;
  onClick: () => void;
  /** 'danger' = ação destrutiva (Remover). */
  tone?: 'default' | 'danger';
  disabled?: boolean;
  title?: string;
  /** Classe extra no ícone (ex.: sino preenchido quando há alarme). */
  iconClassName?: string;
}

export function DeviceCardActionBar({ actions }: { actions: CardAction[] }) {
  if (actions.length === 0) return null;
  return (
    <div className="flex flex-wrap items-center gap-1 border-t border-border pt-2">
      {actions.map((a) => {
        const Icon = a.icon;
        return (
          <button
            key={a.key}
            type="button"
            onClick={a.onClick}
            disabled={a.disabled}
            title={a.title ?? a.label}
            className={[
              'inline-flex items-center gap-1.5 rounded-md px-2 py-1 text-xs font-medium transition-colors',
              'disabled:cursor-not-allowed disabled:opacity-40',
              a.tone === 'danger'
                ? 'text-red-500 hover:bg-red-50 hover:text-red-700 dark:hover:bg-red-500/10'
                : 'text-muted-foreground hover:bg-muted hover:text-foreground',
            ].join(' ')}
          >
            <Icon className={`h-3.5 w-3.5 ${a.iconClassName ?? ''}`} />
            <span className="hidden sm:inline">{a.label}</span>
          </button>
        );
      })}
    </div>
  );
}
```

O rótulo é `hidden sm:inline` de propósito: em telas estreitas o rodapé volta a ser só ícones, sem quebrar linha.

```tsx
/**
 * Modal de telemetria da controladora — lista todos os pontos com o valor
 * vivo formatado e a hora da leitura (mesma experiência do modal de câmeras).
 */
function ControllerTelemetryModal({
  controller,
  live,
  showIp,
  onClose,
}: {
  controller: Controller;
  live: TelemetryMap;
  /** IP:porta é informação de rede — só perfis administrativos veem. */
  showIp: boolean;
  onClose: () => void;
}) {
  const t = useT();
  const camera = asCamera(controller);
  return (
    <div className="fixed inset-0 z-50 flex items-center justify-center bg-black/40 p-4">
      <div className="w-full max-w-md rounded-xl border border-border bg-card p-6 shadow-xl space-y-4 max-h-[85vh] overflow-y-auto">
        <div className="flex items-center justify-between">
          <h3 className="text-sm font-semibold text-foreground">
            {t('Telemetria —')} {controller.name}
          </h3>
          <button
            type="button"
            onClick={onClose}
            className="rounded-md p-1 text-muted-foreground hover:bg-muted"
          >
            <X className="h-4 w-4" />
          </button>
        </div>
        <p className="text-xs text-muted-foreground">
          {[
            showIp ? `${controller.ip}:${controller.port}` : null,
            controller.manufacturer || null,
            controller.profileLabel || null,
          ]
            .filter(Boolean)
            .join(' — ')}
        </p>
        <ul className="divide-y divide-border rounded-lg border border-border">
          {controller.points.map((p) => {
            const entry = liveOrSeed(camera, p.tag, live);
            const raw = entry?.value ?? null;
            const n = Number(raw);
            // Memória em kB e RAM em MB ganham auto-escala (kB é ilegível).
            const value =
              raw !== null && Number.isFinite(n) && p.metric === 'memory' && p.unit.trim().toLowerCase() === 'kb'
                ? formatMb(n / 1024)
                : raw !== null && Number.isFinite(n) && p.metric === 'ram_total'
                  ? formatMb(n)
                  : formatPointLiveValue(p, raw);
            const readAt = formatReadTime(entry?.timestamp ?? null);
            const stateLabel = entry?.state ? POINT_STATE_LABELS[entry.state] : undefined;
            return (
              <li key={p.id} className="flex items-center justify-between gap-3 px-3 py-2.5">
                <span className="min-w-0">
                  <span className="block truncate text-sm text-foreground">{p.objectName}</span>
                  <span className="block text-xs text-muted-foreground">
                    {p.tag}
                    {p.unit ? ` · ${p.unit}` : ''}
                  </span>
                </span>
                <span className="shrink-0 text-right">
                  <span
                    className={
                      value !== null
                        ? 'block text-sm font-medium text-foreground'
                        : 'block text-xs text-muted-foreground'
                    }
                  >
                    {value ?? stateLabel ?? t('sem dados')}
                  </span>
                  {readAt && (
                    <span className="block text-[11px] text-muted-foreground">
                      {t('lido às')} {readAt}
                    </span>
                  )}
                </span>
              </li>
            );
          })}
        </ul>
        <div className="flex justify-end pt-1">
          <button
            type="button"
            onClick={onClose}
            className="rounded-lg border border-border px-4 py-2 text-sm font-medium text-foreground hover:bg-muted"
          >
            {t('Fechar')}
          </button>
        </div>
      </div>
    </div>
  );
}
```

O overlay `bg-black/40` é o mesmo dos outros modais do projeto e é correto nos dois temas.

## 7. Modal de diagnóstico — valor do candidato convertido

Em `apps/frontend/src/modules/cftv/components/SnmpDiagnoseModal.tsx`, o valor lido de cada candidato precisa ser **multiplicado pela escala do candidato** antes de formatar. Sem isso, temperatura em mili-°C aparece como `45230` em vez de `45.2°C`:

```tsx
{formatDiagValue(
  m.metric,
  c.value !== null ? c.value * c.scale : null,
  c.unit,
) ?? c.raw ?? '—'}
```

A seleção passa a carregar `{ oid, scale, unit }` (não só a string do OID), tanto na pré-seleção quanto no checkbox — é o que o endpoint de aplicar espera no formato novo:

```tsx
const [selected, setSelected] = useState<Partial<Record<DiagMetric, AppliedOidSelection>>>({});
// checkbox:
checked={selected[m.metric]?.oid === c.oid}
onChange={(e) =>
  setSelected((prev) => {
    const next = { ...prev };
    if (e.target.checked) next[m.metric] = { oid: c.oid, scale: c.scale, unit: c.unit };
    else delete next[m.metric];
    return next;
  })
}
```

Tipo novo exportado em `cftv.service.ts` (e reexportado em `sca.service.ts`):

```ts
export interface AppliedOidSelection {
  oid: string;
  scale: number;
  unit: string;
}
```

com as assinaturas de `applySnmpOids` mudando de `Partial<Record<DiagMetric, string>>` para `Partial<Record<DiagMetric, AppliedOidSelection>>`.
